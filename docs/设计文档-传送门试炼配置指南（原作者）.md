# 传送门试炼配置指南

三种玩法（闯关 / 爬塔 / 试炼）共用一套数据驱动框架：**出什么怪、给什么奖励、BOSS 克制什么，全部写在数据包 JSON 里**，代码只负责「怎么跑」。因此在整合包里改内容不需要碰 Java，也不需要重新编译。

---

## 1. 三种机制是怎么实现的

| | 闯关 CHALLENGE | 爬塔 TOWER | 试炼 TRIAL |
|---|---|---|---|
| 波次来源 | JSON 里的有限列表 | `scaling` 规则按层现算 | 前置波 + 最后一波 BOSS |
| 波次之间 | **停下等玩家决定** | 倒计时结束自动开下一波 | 同闯关 |
| 死亡后果 | **累计奖励清零** | 层数记录按配置保留/回退 | 奖励按配置清空 |
| 进度持久化 | 无（一次跑完就结束） | **按玩家记录已通过层数** | 无 |
| 结束方式 | 打完最后一波自动结算，或潜行右键提前结算 | 死亡 / 潜行右键结算 / 主动退出 | 击杀 BOSS 自动结算 |

**闯关的「自主选择要不要下一波」**：打完一波后会话进入 `AWAITING_DECISION` 状态停住。
玩家右键传送门 = 继续下一波，潜行右键 = 结算离场并把累计奖励拿走。
死亡则累计奖励清零——这是这个玩法的核心风险，所以奖励是**每波累积、离场才发放**，而不是每波直接进背包。

**爬塔的「下次开启从上次停止位置继续」**：已通过的最高层数按玩家 UUID 存进世界存档（`SavedData`），
服务器重启、区块卸载、玩家死亡都不会丢（死亡是否回退由配置决定）。
重新开局时起点 = 记录层数 + 1 + `resume_offset`，所以默认是从「打过的那层的下一层」继续，不重打。

**试炼的「生成克制玩家属性的 BOSS」**：开局瞬间采集玩家属性快照（护甲、韧性、生命、攻击力、
移速、主手武器类型、主手附魔、是否穿鞘翅），然后用这份快照去筛词条池，命中的词条里按权重抽若干条，
贴到 BOSS 身上。所以同一个传送门，穿重甲的玩家和玩弓的玩家遇到的 BOSS 不一样。

## 2. 快速上手

1. 放下对应模式的传送门方块（`challenge_portal` / `tower_portal` / `trial_portal`，都在创造模式物品栏里）。
2. **空手右键** = 开始试炼 / 继续下一波。
3. **潜行右键** = 结算离场，领取累计奖励。
4. 想一个传送门跑指定的试炼内容：看着它执行 `/tei trial bind <试炼ID>`。

数据包里的示例已经能直接玩（名字用「星罗·」前缀，改名字只要动 `display_name`，ID 由文件名决定）：
- `trial_portal:challenge` → **星罗·闯关**，5 波
- `trial_portal:tower` → **星罗·爬塔**，无尽，每 10 层一个带词条的 BOSS
- `trial_portal:trial` → **星罗·试炼**，1 波小怪 + 带 3 条克制词条的 BOSS

---

## 3. 数据包目录

```
data/<命名空间>/
├── trials/                  每份 JSON = 一个可用传送门开启的试炼，文件名就是试炼 ID
│   ├── challenge.json       → trial_portal:challenge（星罗·闯关）
│   ├── tower.json           → trial_portal:tower（星罗·爬塔）
│   └── trial.json           → trial_portal:trial（星罗·试炼）
└── boss_affixes/            词条池，被上面 trials 里的 affix_pool 按 ID 引用
    ├── anti_armor.json
    └── ...
```

`display_name` 只影响播报和指令输出里显示的名字，可以随便改成中文；
试炼 ID 由文件名决定，必须是 ASCII（`[a-z0-9_]`），因为指令里要按 ID 引用。

把 JSON 放进整合包自己的数据包（`你的整合包/config/...` 或 `saves/<世界>/datapacks/<包>/data/<命名空间>/trials/...`）
也能生效，不必改模组本体。**注意**：`trials/` 与 `boss_affixes/` 是分开的两份目录，
词条写一次可以被多份试炼引用，改一条就影响所有引用它的地方。

改完用 `gradlew checkTrialData` 校验，不用开游戏。

## 4. 试炼定义（`trials/*.json`）

### 顶层字段

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `mode` | string | — | `challenge` / `tower` / `trial`，**决定玩法** |
| `display_name` | string | 文件名 | 播报与指令里显示的名字 |
| `endless` | bool | 按模式推断 | 手写覆盖；`tower` 恒为无尽 |
| `spawn_radius` | double | `6.0` | 以传送门为中心的水平生成半径（格） |
| `spawn_height` | double | `3.0` | 生成时的垂直偏移范围（格） |
| `abandon_distance` | double | `-1` | 离传送门超过这个距离视为放弃；`-1` = 用配置里的默认值，`0` = 关闭检查 |
| `waves` | array | `[]` | 有限波次列表（见下） |
| `scaling` | object | `null` | 爬塔的按层缩放规则；`mode: tower` 时必填 |
| `boss` | object | `null` | 试炼 BOSS 描述；`mode: trial` 时必填 |

未知字段会被忽略，可以写 `comment` 之类的备注字段方便自己读。

### `waves[]` 波次

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `title` | string | 「第 N 波」 | 屏幕大标题；写 `%s` 会替换成玩家名 |
| `mobs` | array | — | 本波生成的怪，不能为空 |
| `rewards` | array | `[]` | 通过本波累加到待结算池的奖励 |
| `intermission_ticks` | int | `-1` | 本波之后到下一波的间隔（20 tick = 1 秒）；`-1` = 用配置默认值 |

`mobs[]` 元素：

| 字段 | 类型 | 说明 |
|---|---|---|
| `entity` | string | 实体 ID，如 `minecraft:zombie` |
| `count` | int | 数量 |
| `nbt` | string | 可选，SNBT，合并进实体（例：`{ArmorItems:[{},{},{},{id:"minecraft:diamond_helmet",Count:1b}]}`） |
| `boss` | bool | 是否按 BOSS 处理：会走词条选取与血量补满流程 |

`rewards[]` 元素：`item`（物品 ID）、`count`（数量）。

### `scaling` 爬塔缩放规则

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `health_multiplier_per_floor` | double | `0.18` | 第 n 层血量 = 基础 × (1 + (n-1) × 该值) |
| `damage_multiplier_per_floor` | double | `0.06` | 每层攻击力倍率增量 |
| `count_per_floor` | double | `0.2` | 每层怪量增量（叠加在 `tiers[].count` 上） |
| `max_count_per_entry` | int | `12` | 单条生成配置的数量上限 |
| `intermission_ticks` | int | `-1` | 每层之后的间隔 |
| `tiers` | array | — | 层段表，按顺序取第一个命中的，必须覆盖到你打算放的最高层 |
| `rewards` | array | `[]` | 发奖用的奖励 |
| `reward_every_floors` | int | `5` | 每几层发一次奖；`<= 0` 不发 |
| `boss_every_floors` | int | `0` | 每几层刷一个 BOSS；`0` = 不刷 |
| `boss_affix_pool` | array | `null` | BOSS 层的词条池；为空则用全部已加载词条 |

`tiers[]` 元素：`from`、`to`（层数区间，含两端）、`mobs`（候选怪物 ID 列表，按层数轮换）、
`count`（基础怪量）、`boss`（该层段是否整体按 BOSS 处理）、`boss_affix_pool`（该层段专用词条池）。

**约定**：BOSS 层的怪取该层段 `mobs` 里的**第一个**。所以想让 30 层以上刷掠夺者当 BOSS，
就把 `"minecraft:ravager"` 写在那个层段的 `mobs[0]`。

### `boss` 试炼 BOSS

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `entity` | string | — | 用哪个实体当 BOSS |
| `name` | string | 实体原名 | BOSS 名称；`%s` 替换成玩家名 |
| `affix_count` | int | `-1` | 携带词条数量；`-1` = 用配置默认值 |
| `affix_pool` | array | 全部词条 | 候选词条 ID 列表 |
| `rewards` | array | `[]` | 击杀奖励——**质变材料写在这里** |

示例里的质变材料是 `minecraft:nether_star` + `minecraft:diamond_block`，
换成你自己的材料只需要改 `boss.rewards` 的 `item` 字段。

## 5. BOSS 词条（`boss_affixes/*.json`）

一条词条 = **判据（什么玩家会遇到它）+ 效果（它把 BOSS 改成什么样）**。

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `display_name` | string | 文件名 | 播报用，玩家会看到「BOSS 克制词条：破甲、碾碎、追猎」 |
| `weight` | double | `1.0` | 抽样权重，越大越容易中 |
| `counters` | object | — | 判据，见下表 |
| `attributes` | object | `{}` | 属性 ID → `{ "op": ..., "value": ... }` |
| `immune_to` | array | `[]` | 免疫列表，见下 |
| `melee_damage_type` | string | `""` | 把 BOSS 的**近战**伤害改成指定伤害类型 |
| `effects` | array | `[]` | 给 BOSS 自身挂的药水效果 |
| `equipment` | object | `{}` | 槽位 → 物品 ID |
| `equipment_enchantments` | object | `{}` | 槽位 → `["附魔ID:等级", ...]` |
| `name_suffix` | string | `""` | 追加到 BOSS 名字后的后缀，如 `"·破甲"` |
| `name_color` | string | `""` | 名字颜色，6 位十六进制，如 `"FF5555"` |

### `counters` 判据

**所有写出来的条件之间是「与」关系**；没写（保持默认值）的条件不参与判断。

| 字段 | 类型 | 说明 |
|---|---|---|
| `min_armor` | double | 玩家护甲值下限 |
| `min_armor_toughness` | double | 护甲韧性下限 |
| `min_max_health` | double | 最大生命值下限 |
| `min_attack_damage` | double | 攻击伤害下限 |
| `min_movement_speed` | double | 移动速度下限 |
| `weapon` | string | `any` / `melee` / `ranged` / `unarmed`（按主手武器判断；弓、弩、三叉戟都算远程） |
| `enchantments` | array | 主手武器带有其中**任意一个**附魔即命中 |
| `elytra` | bool | `true` = 要求穿了鞘翅，`false` = 要求没穿 |
| `always` | bool | `true` = 无条件成立（保底词条） |

「或」关系只能靠写多条词条来表达——比如「鞘翅玩家」和「高移速玩家」是两条词条，
而不是一条词条里两个条件（那样会变成「既穿鞘翅又移速高」）。
用 `/tei trial profile` 可以看自己会被哪些词条命中，调判据时很好用。

### `attributes` 属性修改

```
"attributes": {
  "minecraft:generic.max_health":     { "op": "multiply_base", "value": 0.5 },
  "minecraft:generic.armor":          { "op": "add",           "value": 8.0 },
  "minecraft:generic.knockback_resistance": { "op": "set",     "value": 1.0 }
}
```

`op` 取值：`add`（加算）、`multiply_base`（按基础值乘算）、`multiply_total`（作为总倍率修正）、
`set`（直接设定）。属性注册名在 1.20.1 带 `generic.` 前缀；写成 `minecraft:max_health`
（1.21 之后的写法）也能识别，两种都接受。

### `immune_to` 免疫

简写：`all`、`projectile`、`fire`、`explosion`、`fall`、`magic`、`melee`；
也可以直接写伤害类型 ID，如 `minecraft:wither`。
`melee` 的判定是「直接来源是生物」，因此近身范围伤害也会被算作近战。

### `melee_damage_type`：让 BOSS 无视护甲

把 BOSS 的近战伤害换成另一种伤害类型。最实用的用法是改成 `minecraft:magic`——
魔法伤害无视护甲，于是「堆护甲的玩家」会被硬克。这也是示例词条 `anti_armor` 的做法。

### `effects` / `equipment`

```
"effects": [
  { "effect": "minecraft:regeneration", "amplifier": 1, "duration": -1 }
],
"equipment": {
  "chest": "minecraft:diamond_chestplate"
},
"equipment_enchantments": {
  "chest": ["minecraft:thorns:3"]
}
```

`duration: -1` 表示无限。槽位名：`mainhand` / `offhand` / `head` / `chest` / `legs` / `feet`。
BOSS 的装备掉率被设为 0，不会变成免费装备。

### 示例池里 8 条词条的克制逻辑

| 词条 | 命中判据 | 效果 | 玩家该怎么应对 |
|---|---|---|---|
| 破甲 | 护甲 ≥ 12 | 近战改魔法伤害（无视护甲）+ 血量 ×1.5 | 堆韧性/减伤不如堆输出速杀 |
| 碾碎 | 生命 ≥ 30 且韧性 ≥ 4 | 攻击力 ×1.8、免疫击退、血量 ×1.8 | 硬拼不划算，拉开距离 |
| 追猎 | 主手是远程武器 | **免疫弹射物** + 移速 ×1.5 + 索敌 48 + 持续回血 | 必须换近战 |
| 荆棘 | 主手是近战武器 | 护甲 +8、钻石甲带荆棘 III | 打它自己掉血，换远程或用环境 |
| 耐火 | 主手带火焰附加/火矢 | 免疫火焰 | 火焰流派失效，换物理 |
| 禁空 | 穿鞘翅 | 索敌 64 + 移速 ×1.4 + 缓降 | 飞着耗不掉了 |
| 疾走 | 移速 ≥ 0.12 | 移速直接设 0.42 + 抗击退 0.6 | 跑不掉 |
| 坚壁 | 无条件（保底） | 血量 ×2、护甲 +6 | 保证任何玩家都至少有一条词条 |

「追猎」是唯一一条**完全免疫某种伤害**的词条，用来强制玩家换打法；
其余都是加强而不是堵死。如果你担心某条太狠，调低它的 `weight` 就能减少出现频率。

## 7. 指令（需要权限等级 2）

```
/tei trial list                        列出已加载的试炼
/tei trial start <试炼ID>              在自己脚下直接开局（不用放传送门）
/tei trial stop                        中止当前会话（不发奖励）
/tei trial status                      查看会话状态与爬塔层数
/tei trial bind <试炼ID>               把正在看的传送门绑定到指定试炼
/tei trial floor [层数]                查看 / 设置自己的爬塔层数记录
/tei trial profile                     显示自己的属性画像 + 会被哪些词条命中
/tei trial affixes                     列出已加载的词条
```

调数据包时最顺手的流程：`/tei trial profile` 看判据命中情况 →
改 JSON → `/reload`（数据包会重载，不用重启）→ `/tei trial start <ID>` 直接试。
`/reload` 会重新跑两个加载器，出错的定义会被跳过并在日志里写明原因，不会影响其它定义。

## 8. 验证数据包：`gradlew checkTrialData`

不开游戏、不需要接受 EULA，把 `data/` 下的 JSON 用真实模型类跑一遍：

```bash
./gradlew checkTrialData
```

它会检查：JSON 能否反序列化、必填字段是否齐、`mode` 是否合法、
每一波/每一层能否取到内容、爬塔的 `tiers` 有没有覆盖到你打算放的层数、
词条池里的 ID 是否真实存在、词条权重是否为正、词条有没有写判据。
有问题的条目会打印出来并以非 0 退出码结束。

`gradlew build` 会自动带上这个检查；只想打包时用 `gradlew build -x checkTrialData`。

## 9. 已知限制

- **每个玩家同时只能有一场试炼**。会话绑定在玩家身上、生成中心绑定在开局时那个传送门的位置上，
  所以中途换另一个传送门继续，会因为「离开范围」判定被中止。多人各打各的没问题，但做不了组队闯关。
- **波次判定依赖区块加载**。传送门所在区块没加载时会跳过本轮判定（避免把「没加载」误判成「已清完」）；
  反过来说，如果你把刷出来的怪拉出很远、导致它们所在区块卸载，这些怪会被当成已消失，本波直接算通过。
  用 `abandon_distance`（默认 48 格）能挡住大部分这种情况。
- **怪按原版环境规则生存**：白天刷的幻翼会被烧、末影人会瞬移、僵尸会变成溺尸，
  这些都不受本模组控制。要固定行为请在 `nbt` 里关掉对应属性（如 `{NoAI:1b}`）。
- **试炼的「克制」是抽样，不是每次都能完美克制**：词条按权重随机抽，
  加了新词条后旧词条出现率会摊薄，必要时用 `affix_pool` 限定候选范围。
- **传送门贴图复用原版方块**（`end_portal_frame_top` / `purpur_block` / `crying_obsidian`），
  所以仓库里不需要带任何 PNG。换美术只要改
  `assets/trial_portal/models/block/*.json` 里的 `textures.all`。
- **传送门方块目前是实心方块**，不是真正的可穿越传送门——它的作用是「试炼入口/交互终端」。
  要做成走进去传送，需要额外加方块碰撞形状与传送逻辑。
