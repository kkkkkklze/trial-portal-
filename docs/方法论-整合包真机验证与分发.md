# 方法论：整合包里的真机验证与分发

> 这份文档写的不是"这个模组做了什么"（那是 `开发文档.md`），而是**我是怎么知道它做对了的**，
> 以及换一个工程/换一个整合包时怎么把同一套流程搬过去。里面每条都对应一次真实的代价，
> 标了日期号（㉑–㊺ 是 `开发文档.md` §10 编年史的切片编号）。

## 0. 要解决的三个问题

给一个装别人整合包的模组做交付，卡点从来不是"代码写不写得出来"，而是这三件事：

1. **看不见**——无头环境里没有那些 mod 的注册表，跑起来的东西和玩家跑起来的东西不是同一个；
2. **改不动**——真机验证要有人点鼠标，而"人"通常是作者本人，他一忙整条验收就停摆；
3. **带不出去**——工程里全是本机路径、玩家名、整合包名，随手一推就把隐私发出去了。

下面每一节都在解决这三条之一。

## 1. 四层验收：每层只准证明自己能力之内的东西

| 层 | 是什么 | 能证明 | **不能**证明 |
| --- | --- | --- | --- |
| L1 离线数据门 | `./gradlew checkTrialData`（`src/tools/java` 里的校验器，同一套模型类） | JSON 字段齐不齐、引用自不自洽、语言键对不对得上、台账数字（配置项数、生成点数、配方数） | 运行期会不会真的读到 |
| L2 无头断言 | `./gradlew selfTest -PselfTest` → `run/selftest-result.txt` 的 `PASS=n FAIL=0` | 状态机、数值、结算、递进账、坏数据拒绝 | 任何客户端渲染、任何网络往返、任何"装了第三方 mod 才成立"的事 |
| L3 真机桥接 | `playtest-bridge`（环回 HTTP 9876）驱动**玩家那个整合包**里的客户端 | 反射接得上、注册表里有这个 id、方块交互真的生效、别的 mod 的怪真能被刷出来 | 好不好看（除非截图） |
| L4 像素判据 | 桥接的 `screenshot` + PIL 裁剪后**看图** | 布局重叠、译文缺失、图标没渲染、颜色语义 | —— |

**这条分层是整套流程的地基**，因为它的反面我全踩过：

- L1/L2 全绿但事实是假的：`runData` 根本不跑模组构造函数（1.20.1 源码核过），所以"数据能生成"曾经一直靠猜（㉑）；
- L2 绿着但 L4 抓到真缺陷：tooltip 只画标签不画值，因为译文里没有 `%1$s`，格式化器静默丢参数——624 条纯逻辑断言一条都没红（另一工程，同一族教训）；
- 只看 L3 的返回值会误判：右键"没反应"其实是打中了、开成了会话、又被脚本自己的 `tp` 拽出范围（㉞ 那一轮）。

⇒ **规矩：一条性质属于哪层，就去哪层证；跨层的性质必须在两层各留一条。** 客户端渲染的代码四道无头门永远不会执行，
所以要在乎它就得看图；反过来，把能搬进纯类的判断留在客户端里，就等于放弃了 L2。

## 2. 工具清单（都在仓库里，不是一次性脚本）

| 工具 | 干什么 | 关键参数 / 产物 |
| --- | --- | --- |
| `src/tools/java/.../TrialDataCheck.java` | L1 校验器 | 台账式：词条/试炼/房间/副本/配方/守塔/语言键/配置/生成点，一条对不上就红 |
| `TrialSelfTest` | L2 自驱断言 | 开关 `-PselfTest`；判据要**当场推导期望值**，不抄账本 |
| `../playtest-bridge-1.20.1` | L3/L4 驱动 | `POST /api/`：`status/cmd/key/screen_click/widgets/screenshot/look/mouse_move…`；**dev-only，永不随包发布** |
| `tools/census_to_pack.py` | 普查 → 递进数据包 | `--floors 100 --defenses N --overlay <名>`；六道判据 + 出包后按产物复查 |
| `tools/make-dist.py` / `verify-dist.py` | 打包 / 独立验证 | 白名单 + REQUIRED + scrub + refuse 四件套；`verify-dist --build` 会真编译解压出来的树 |
| `verify-logs/*.py` | 一次性驱动 | **故意不入库**（`.gitignore` 里），文档里引用文件名只当"作者机器上的指针" |

界线很清楚：**能被别人复跑的叫工具，只为我这一轮跑通服务的叫脚手架**，脚手架不进任何交付物，
但它必须留在 `verify-logs/` 里，因为下一次复现同一条判据时，重写一遍的代价我付过。

## 3. 影子实例：在别人的整合包里验证，而不碰别人的整合包

（㊸ 定型）要验"新版本在你的包里怎么样"，绝不能往用户实例里写东西。做法：

1. 用**硬链接**把实例的 `mods/`、`config/`、`resourcepacks/` 复制成 `agent-shadow/`——不占空间、不动原文件；
2. 只有被测 jar 与桥接 jar 是影子目录自己的副本；
3. 启动命令按 `versions/<实例>/<实例>.json` 复刻（`${classpath}`/`${natives_directory}`/`${auth_*}` 自己填），
   classpath 要**手工补上** forge 的 `universal` 与 `client` 两枚（profile 的 libraries 里没有 forge 本体）。

三个真实坑：四段库名 `g:a:classifier:version` 别把 classifier 当 version；jvm 参数与 game 参数分两张表
（混在一起主类会跑到中间，java 报 `Unrecognized option: --username`）；`@argfile` 里带空格或 `;` 的整条加引号，
但**别在循环里对 `-` 开头的行 `continue`**（会把 `-cp` 整条丢掉）。

> 代价记录：㊸ 之前我直接把 jar 拷进过用户实例，事后从备份逐字节还原。
> 从此"复制不移动"包括**别往用户实例里写**——这条已经写进工程纪律。

## 4. 驱动真客户端：哪些通道能用，哪些是陷阱

- **OS 级输入能用，条件是窗口在前台且没最小化**（㊺ 更正）。此前我记的是"SendInput 永远进不去"，错在没限定条件：
  用户关掉占前台的程序之后，`press_key Escape` 直接开出 `PauseScreen`（返回 `foregroundStatus: matched`）。
  仍然成立的一半：代理会话里 `activate_window` 会报 `foregroundHwnd=0`，**抢不到前台**，所以不能把 OS 输入当默认通道。
- **桥接的 `key` 只认 KeyMapping 名**（`use`/`attack`/`chat`/`hotbar.1`/自定义 `key.<modid>.<名>`）；
  `escape` 没有映射，屏内导航要用 `screen_key`（GLFW 整数码：ESC=256、TAB=258、ENTER=257）。两条通道别混用。
- **`key.use` 要 down→按住→up**，`tap` 经常打不中方块；`key.attack` 在有的包里 `down:true` 也不破坏方块
  （别的 mod 抢了同一枚鼠标左键）——遇到这种判据要么换命令路径，要么请用户手点，别记成"我们的方块拆不掉"。
- **创造飞行开不起来**：`key.jump` 连点两次不进入飞行态（原版数的是真实按压时刻），所以"按住 jump"只是原地跳。
- **瞄准别用 `/tp … facing`**：它按**脚**算俯仰，而准星起点在**眼睛（脚 +1.62）**，1 格高的面会被掠过。
  自己按 `yaw=atan2(-dx,dz)`、`pitch=atan2(-(眼-面心),水平距离)` 算，或者用桥的 `look`（直接改实体朝向）。
- **`inGame:true` ≠ 能收键**：那一刻可能还在加载地形，注入会被整段吞掉。进世界后再等 ~30 秒，每步回读 `status.screen`。
- **窗口被最小化**的症状很隐蔽：桥报 `gui:"1x1"`、控件 `bounds` 出现负数，此时所有 `screen_click` 全打偏。
  判据＝读 `status.gui`；恢复＝`ShowWindow(hwnd,9)` + `MoveWindow`。
- **世界在不在 tick** 不要看 `screen`：用 `entities` 连读两次比大小。失焦时有的包（带 FancyMenu）只冻结世界不弹菜单。
- **截图口径**：像素 = GUI 逻辑尺寸 × 缩放档（本机 427×240 → 854×480），所以裁剪在像素空间做，
  并且 `Screenshot.grab` 是 io 线程写盘的——拿到返回路径后要轮询到 PIL 能 `load` 再裁（0.4–2 秒）。
  文件名会被洗成 ASCII，tag 一律用英文。
- **判据必须落在同一个可观察对象上**（㊸ 的代价）：`probe` 打的是"最近的一只"，我却按 `type=skeleton` 读属性，
  于是得出"写了 500 血量没动"的假结论。写和读要钉在同一只实体上。
- **假阳性的一种特定形状**：把聊天压成无空格字符串再匹配——被拒的命令会把原文回显在聊天里，
  `… run say EXIT-6<--[此处]` 里就含 "EXIT-6"，于是"扫到 13 台门"。要匹配**成功输出的形状**。

## 5. 数据流水线：从"包里有哪些怪"到"能交付的数据包"

```
/tei mob census request  →  玩家运行时写出 mob-census.tsv      （无头环境拿不到别的 mod 的注册表）
        ↓
tools/census_to_pack.py  →  分档 / 逐层 / 守塔关卡，六道判据剔非战斗实体，留痕不静默
        ↓  audit_output_shapes（按最终产物再扫一遍）
checkTrialData 复扫生成物（盖在工程内容之上，用同一套模型类）
        ↓
-PpackOverlay=<名> build  →  jar 自带内容（新建存档开箱就有；世界 datapack 会盖住 jar，所以别混放）
        ↓
装进实例 → 真机复验（L3/L4）
```

三条不可让的纪律：

1. **期望值当场推导**，不抄账本——生成器不许写死怪名或血量，换一份普查重跑，档位自己移动；
2. **剔除要留痕**——每一条被丢的条目都打印原因，"静默丢"是数据面最常见的假绿；
3. **约束要做成会自己变红的门**，不是一段注释。`audit_output_shapes` 扫的是**出包后的产物**，
   因为前五道判据挡的是"进池子之前"，而池子会被 `--add-exclude` 与以后的新模组绕过。

## 6. 变异抽查：证明判据真的在咬

每条新门除了自带探针，还要**手动把实现改坏一次**，指到具体哪条断言红、红成什么数字。
这一路抓到的真东西：`DefenseDefinition.copyWave` 漏抄一个字段、隔间编号段重叠、
配方产物按方块归类归错族、"删掉战利品表 ⇒ FAIL=2 并点名 arena_exit"。
反面也抓到自己：探针打在**被常量折叠吃掉的 static 保险丝**上会假绿，被 TOOTHLESS 点名过——
所以"打空"和"没有缺陷"是两件事，得让打空本身变红。

## 7. 发布链：三道闸 + 一次快进

```
源仓库提交（显式路径 add，不用 -A：常有并行会话的在途改动）
   ↓ verify-logs/pub_publish.py：把源树脱敏后重放进 trial-portal-public
   ↓ 泄露闸门：扫工作区 + 整条历史 blob（本次 112 文件 / 262 blob）
   ↓ L3 深度安全审查（qodersec，推送前自动跑）
   ↓ 从公开副本 git push origin main —— 快进，绝不 force
   ↓ 验收只认远端 sha（api.github.com + curl -4），push 的 stdout 不算证据
```

打包器 `make-dist.py` 的四件套，每一件都对应一次真实事故：

- **白名单**（`include_files`/`include_dirs`）：黑名单是开口的，哪天加一目录秘密就静默发出去了；
- **REQUIRED**：白名单会**静默漏**——第一版打出来的包看着正常、根本构建不了，是独立验证器发现的；
- **scrub**（按文件的映射表）：机器路径/玩家名/整合包名**只在进包的路上**替换，工作区保持可用；
- **refuse**（扫描表）：scrub 没覆盖到的文件里出现这些形状 ⇒ **拒绝出包**，不是警告。
  ㊺ 那次就是它拒的：我把整合包名写进了源码注释。

顺手记一条**还没解决的不一致**：分发件里禁整合包名，而公开仓的 `docs/开发文档.md` 里它有 30 处
（编年史正文，两道闸门清单不同）。要么把镜像的闸门也加上这条，要么承认"编年史可以带包名"——需要作者定。

## 8. 环境层的坑（换机器/换会话最容易复发的）

- **JAVA_HOME 是本机 JRE27**：动过 `build.gradle` 后新 daemon 必崩在 `major version 71` ⇒ 命令前钉 JDK17。
- **`python` 是商店占位**（静默无输出、退出码 44/49）⇒ 一次性脚本要用真解释器的绝对路径来调，
  具体路径属本机信息，不写进文档；`verify-logs/` 里的脚本都按这个方式跑。
- **CJK 不进 argv / heredoc** ⇒ 一次性脚本一律落文件跑；PowerShell 脚本必须纯 ASCII（要中文就放数据文件里）。
- **Git Bash 会重写以 `/` 开头的参数** ⇒ `cmd` 里的命令**不要带前导斜杠**，或用 `MSYS_NO_PATHCONV=1`。
- **别把长构建管道交给 `head`/`tail`**：SIGPIPE 截断后退出码仍是 0 ⇒ 落盘日志再 grep，并核对阶段标记有没有出现。
- **`runGameTestServer` 退 0 也可能一条没跑**：残留 daemon 子 JVM 锁住 `run/logs` 会让它启动即抛，
  验收只认 `N required tests passed` 那一行，解药 `./gradlew --stop`。
- **长驻/带 GUI 的进程用工具的 `run_in_background` 起**，`DETACHED_PROCESS` 也躲不过进程树回收；
  而 `TaskStop` 只杀包装进程，游戏 JVM 可能还活着占着端口——**判据不能是"端口有响应"，要按命令行特征数 PID**。

## 9. 复盘：真正救过我的几条

1. **求证优先于记忆**——三次"我记得是这样"被 grep/字节码/看图当场推翻（恶魂式远程怪、`Modifiers` 目录单复数、OS 输入）。
2. **不认自述，只认同轮回读的产物**——日志说"已加载"不算，`zipfile` 读进 jar 数条目才算；sha 会因时间戳漂，逐条目 CRC 才是身份。
3. **"看起来没生效"先找一个幂等入口再点一次**——服务端回 `placement no-op` 就证明第一次的改动活着，比读代码快。
4. **相机角度会伪装成功能没生效**——粒子/弹体在脚前 1–3 格时，pitch 14–18° 的截图里它们在画面外；改 pitch≈60° 才拍得到。
5. **权限不够时报的是 parse 错，不是权限提示**（brigadier 的 `requires` 失败形状），极易误判成"指令没注册"。
6. **别把 `execute in <自家维度> run tp` 当"进场地"**——只有走入口路径才建台，直接 tp 就是掉虚空（我在极限模式里摔死过一个角色）。
7. **一次跑测别用上一步留下的现场**——会话、位置、聊天历史都会串；一个脚本只测一件事。
8. **收尾三件事**：删掉影子目录里的桥接 jar 副本、还原改过的 `run/config/*.toml`、再跑一遍两道门证明没被污染。

## 10. 换工程怎么搬

通用的：四层验收的分法、影子实例、桥接驱动的通道与坑、"判据落在同一可观察对象上"、
变异抽查、发布三道闸、打包四件套、环境清单。

不通用、必须重做的：L1 的台账条目（每个工程要自己定义"哪些数字必须对得上"）、
L2 的断言（要搬进不 import MC 的纯类才测得到）、普查判据（不同整合包的"假怪"形状不一样）。

搬的时候先做一件事：**把上面 §1 那张表的"不能证明"列贴在自己工位上**。
这一路所有的返工，都是因为我拿一层的绿去回答了另一层的问题。
